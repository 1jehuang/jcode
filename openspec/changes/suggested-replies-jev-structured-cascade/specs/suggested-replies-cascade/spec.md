## MODIFIED Requirements

### Requirement: Two-Stage Macro/Micro Branching with OpenJev / Laya SystemOne and OpenGF
The system SHALL execute a two-stage cascade at turn completion using a structured `SuggestedRepliesContext` (`last_user_message`, `last_assistant_message`, `assistant_options`, `pending_todos`, `recent_turns`, `language_is_cyrillic`). Both Iteration 1 and Iteration 2 SHALL pass a structured JSON `state` object to SystemOne (`build_structured_systemone_state`). Iteration 1 determines the macro conversation branch (via SystemOne `choice`/`noul` against the structured context `state` when `use_open_gf = false`, or via OpenGF `Sidecar` / configured `[providers.*]` / external OAuth fallback routes with `"store": false` when `use_open_gf = true`), and Iteration 2 scores candidate actions against `{ branch, last_user_message, last_assistant_message, assistant_options, pending_todos, candidates: { cand_0..cand_N } }` via the configured SystemOne provider (`JevProvider::Laya` over loopback or trusted Tailscale/private LAN HTTP, or `JevProvider::OpenJev` / `TypeSafe` / `OpenRouter` / `Aimlapi` / `Jcode`). When the active SystemOne provider supports `choice` questions and at least two candidates are present (`candidates.len() >= 2`), Iteration 2 SHALL submit both a comparative `best_candidate` (`type: "choice"` over `cand_0..cand_N`, capped so total questions `<= 24` to respect `MAX_QUESTIONS`) and individual `cand_0..cand_N` (`type: "noul"`) questions in a single batch request, combining `noul`, `choice.probabilities`, and rank prior in `calibrate_micro_score_with_choice` (falling back to `noul`-only when `candidates.len() == 1` or when the provider only accepts `noul`). Existing public entry points (`evaluate_cascade`, `score_locally_from_context`, `build_micro_scoring_noul_questions`) SHALL remain backward-compatible.

#### Scenario: Default Action promotion and secondary suggestions distribution
- **WHEN** candidate actions are scored (via joint `choice + noul` SystemOne evaluation or deterministic local scoring) and sorted by `confidence` descending
- **THEN** if the top candidate has `confidence >= confidence_threshold`, it is assigned to `defaultAction` and up to `max_secondary_suggestions` remaining candidates are placed in `secondarySuggestions`; otherwise `defaultAction` is `None` and up to `max_secondary_suggestions` candidates are placed in `secondarySuggestions`.

#### Scenario: Structured JSON state and joint choice+noul micro-scoring batch
- **WHEN** Iteration 2 evaluates `>= 2` candidate replies on a provider that supports `choice` (`Laya`, `OpenJev`, `TypeSafe`, `OpenRouter`, `Aimlapi`)
- **THEN** the request `state` is a structured JSON object containing `candidates.cand_0..cand_N` (plus conversation and `pending_todos` context), the `questions` map contains `best_candidate` (`type: "choice"`) alongside `cand_0..cand_N` (`type: "noul"`) within the provider's question limit, and `calibrate_micro_score_with_choice` fuses the `noul` probability, `best_candidate` softmax probability, and rank prior; if only 1 candidate is present or the provider is `Jcode` (`noul`-only), Iteration 2 omits `best_candidate` and evaluates `cand_0` via `noul`.

## ADDED Requirements

### Requirement: Assistant Question Option Extraction and Language-Aware Dynamic Candidate Pool
The system SHALL inspect `last_assistant_message` for explicit questions or numbered/bulleted options and detect the user's conversation language (Cyrillic/Russian vs English), feeding extracted options and `pending_todos` into both the OpenGF prompt and the deterministic local candidate builder so fallback or `use_open_gf = false` evaluations produce context-relevant replies in the user's language.

#### Scenario: Russian conversation or assistant option list without OpenGF
- **WHEN** `use_open_gf = false` (or OpenGF routes are unreachable) and the recent user turn is in Russian or the assistant message ends with numbered/bulleted options or pending `todo` items
- **THEN** the candidate pool prioritizes direct responses to the assistant's options, the next pending `todo` item, and Russian-localized workflow actions rather than static English-only strings.
