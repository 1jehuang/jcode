# Local Jarvis request audio history (Linux)

`/voice history on` opts in for the currently attached always-on Jarvis session only. It cannot recover earlier requests. Nothing changes in other sessions or by default. Session detach, client exit or listener replacement discards the history.

* `/voice history status`, `clear`, or `off`: inspect, forget the saved clips, or forget and disable. Clearing invalidates unfinished candidates; `off` also stops replay.
* `/voice history replay` plays the latest final accepted request once with `paplay`. Add `1`, `2`, or `3` to select by recency. The TUI displays a short preview of its paired final transcript. Playback suppresses Jarvis capture and waits for the existing speaker-decay interval before accepting new audio. Busy audio can refuse playback rather than interrupt someone.
* For a spoken “play what I said before this,” the assistant should use `python3 scripts/jarvis_audio_history.py previous` from the local checkout. `previous` selects the newest retained ID older than the latest dispatched voice request, even if that request was too long to keep. The same helper accepts `on`, `off`, `clear`, `status`, and `replay [1-3]`. It uses the owner's private session socket, never returns a transcript or audio, and does not require enabling a server API. `status` distinguishes player start from successful process completion; neither confirms speaker audibility.

**What is saved:** up to three complete utterances (mono signed 16-bit, 16 kHz, 20 seconds / 640,000 PCM bytes each). The source is the same segmented PCM submitted to the existing Nari streaming job, including its normal onset/trailing padding. Overlong clips are discarded, not silently truncated. The ring expires clips after ten minutes. While STT and classification are running, bounded candidate audio is transient: empty finals, cancellation, failure and non-addressed speech never become history. A later manual trigger of previously rejected text cannot recover its audio. No room recording, partial-transcript archive, extra STT upload, audio file, or provider-facing replay command is added. Private runtime status includes only clip IDs, enablement and playback/control state, not content.
